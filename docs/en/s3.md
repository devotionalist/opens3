# S3 usage guide

Default endpoint: `http://<s3-host>:8333`. Path style: `http://host:8333/{bucket}/{key}`.

## Auth (SigV4)

Setting Access Key enables mandatory signing:

```bash
export OPENS3_ACCESS_KEY=admin
export OPENS3_SECRET_KEY=secretsecret
opens3 s3 --port 8333 --clerk http://127.0.0.1:9333 --meta-dir ./filer
# For production multi-replica, use --meta-backend postgres + DATABASE_URL (same port also serves /entries /dav)
```

AWS CLI:

```bash
aws configure set default.s3.signature_version s3v4
aws --endpoint-url http://127.0.0.1:8333 s3 ls
```

Without configured keys, development mode is equivalent to **root**, convenient for curl debugging; **production must enable auth**.

## Common supported APIs

| Operation | Notes |
|-----------|-------|
| CreateBucket / DeleteBucket / ListBuckets | Bucket management |
| PutObject / GetObject / HeadObject / DeleteObject | Object CRUD |
| ListObjectsV2 | `prefix` / `delimiter` |
| CopyObject | `x-amz-copy-source` |
| CreateMultipartUpload / UploadPart / Complete / Abort | Multipart upload |
| Put/Get Bucket Versioning | Versioning toggle |
| Put/Get Bucket Lifecycle | Expiration rules (background scan) |
| Put/Get Bucket Policy | JSON IAM-style policies |

Admin console (browser file management, no SigV4 required):

- UI: `GET /admin` or `/admin/ui` — bucket list, upload/download/delete, folder browse
- Status: `GET /admin/api/status`
- FS API: `/admin/api/fs/buckets`, `/admin/api/fs/objects`, `/admin/api/fs/object`
- Webhook: `POST /admin/api/webhooks` `{"url":"http://..."}`
- Directory replicate: `POST /admin/api/replicate` `{"prefix":"/buckets/b","target_filer":"http://other:8333"}`

## Versioning

```bash
# Enable
curl -X PUT 'http://127.0.0.1:8333/mybucket?versioning' \
  -d '<VersioningConfiguration><Status>Enabled</Status></VersioningConfiguration>'

curl 'http://127.0.0.1:8333/mybucket?versioning'
```

After enabling, overwrites generate a `version_id`; deletes can write a delete marker.

## Bucket Policy example

Deny deletes, allow read/write:

```bash
curl -X PUT 'http://127.0.0.1:8333/mybucket?policy' \
  -H 'Content-Type: application/json' \
  -d '{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject", "s3:ListBucket"],
      "Resource": ["arn:aws:s3:::mybucket", "arn:aws:s3:::mybucket/*"]
    },
    {
      "Effect": "Deny",
      "Action": "s3:DeleteObject",
      "Resource": "arn:aws:s3:::mybucket/*"
    }
  ]
}'
```

Evaluation rule: **explicit Deny wins over Allow**; the `root` identity is always allowed.

## Lifecycle

```bash
curl -X PUT 'http://127.0.0.1:8333/mybucket?lifecycle' \
  -d '<LifecycleConfiguration>
    <Rule>
      <ID>expire-logs</ID>
      <Status>Enabled</Status>
      <Filter><Prefix>logs/</Prefix></Filter>
      <Expiration><Days>7</Days></Expiration>
    </Rule>
  </LifecycleConfiguration>'
```

The S3 process scans and deletes expired objects about every 60s.

## Multipart example (curl)

```bash
INIT=$(curl -s -X POST 'http://127.0.0.1:8333/b/large.bin?uploads')
UPLOAD_ID=$(echo "$INIT" | sed -n 's/.*<UploadId>\([^<]*\)<\/UploadId>.*/\1/p')

curl -X PUT "http://127.0.0.1:8333/b/large.bin?partNumber=1&uploadId=$UPLOAD_ID" --data-binary @part1
curl -X PUT "http://127.0.0.1:8333/b/large.bin?partNumber=2&uploadId=$UPLOAD_ID" --data-binary @part2
curl -X POST "http://127.0.0.1:8333/b/large.bin?uploadId=$UPLOAD_ID" \
  -d '<CompleteMultipartUpload></CompleteMultipartUpload>'
```

## SDK notes

- Region can be `us-east-1` (used for path calculation)  
- Disable forced HTTPS / set path-style per SDK docs with `forcePathStyle = true`  
- Intermediate proxies must not rewrite signed headers  

## At-rest encryption (Filer)

```bash
opens3 s3 --encrypt 'your-passphrase' ...
```

Objects are AES-256-GCM encrypted before writing to Volume; lost passphrase means undecryptable data.
